# Спецификация оболочки, стадия 0→1 (черновик)

Источник: TimeSlices_Project_Brief_RU, разделы 5, 7, 9. Здесь — только то, что нужно
для сессии 01 и ближайших. Изменения — через ADR.

## Сущности (EF Core + SQLite)
| Сущность | Поля | Примечание |
|---|---|---|
| `ApplicationUser` | Identity + `AssignedExaminerId` | роли Learner / Examiner / Admin |
| `UserSliceState` | `UserId`, `SliceId`, `State`, `IsRepeat`, `UpdatedAt` | единица состояния = срез (ADR 0014, п. В); тематический срез — единица навигации |
| `Attempt`, `Question`, `Answer` | по brief 9.3 | **не в сессии 01**, схема зарезервирована |

Треки, срезы, примеры, реализации, процессы, кадры **не хранятся в БД**: они читаются из
файлов содержания (`docs/spec/manifest-schema.md`) при старте и кешируются в памяти.
В БД — только то, что относится к пользователю. Это и есть «оболочка читает манифесты».

## Состояния тематического среза (brief 5.3), сессия 01
`Unavailable` → `Available` → `InProgress` → `Done`. Остальные (сдача, экзаменатор) — позже.
Переход `Unavailable → Available` вычисляется, а не хранится: срез доступен, когда все
непосредственные предшественники в `Done` (для того же пользователя). Трек в `prerequisites[].track` —
только подпись ребра; состояние тематического среза в каждом треке = состояние среза (ADR 0014, п. В).

Повторное прохождение (brief 5.3): открыть пройденный срез → если дальше не продвигался, он
просто `InProgress`; иначе — выбор: (1) сброс последующих в `Unavailable` или (2) ничего не
менять, срез `InProgress` с `IsRepeat = true`, для последующих считается `Done`.

## Страницы
- `/` — треки; в каждом — срезы с состоянием; закрытые видны, но не кликабельны.
- `/slices/{id}` — поля раздела 7.1 brief (годы, треки, вводимое решение, связь назад/вперёд,
  пометка актуальности а/б/в с пояснением «зачем это, если код пишет модель»), примеры по
  возрастанию сложности, кнопки «Готово» и «Далее».
- `/slices/{id}/examples/{exampleId}?impl=…` — iframe на `Content/.../implementations/<impl>/<entry>`,
  выпадающий список реализаций, код для показа (с пометками ключевых строк), список процессов.
- `/admin` — список пользователей и их состояний (демо-экзаменатор появится позже здесь же).

## Нефункциональные ограничения 0→1
Без JS-фреймворков и сборщиков; SQLite-файл; один процесс; никакой распределённости.
Контекстный файл, ADR и приёмочные критерии ведутся с первого дня (brief, риск 6).
