# Учебная машина с регистрами (срез `register-machine-1960`)

Редакция 21.10.2026, r1. Статус: ЧЕРНОВИК до утверждения автором. Основание — ADR 0014, п. А (срез 3).

Вторая учебная машина коллекции. Первая — машина с одним аккумулятором по образцу EDSAC
(`stored-program-1949`, описана в `docs/slices/hw-01_cpu-cycle.md`, раздел 5). Обе — учебные,
не эмуляция настоящих машин (CLAUDE.md). Эта машина — «привычная»: несколько регистров,
индексный регистр, константа прямо в команде, сравнение и условный переход. Её программа читается
как программа на любом современном ассемблере, и она **не переписывает сама себя**.

Задача на обеих машинах одна: заполнить таблицу квадратов (и кубов) чисел от 0 до N−1,
N = 10 или 100, только сложением. Одинаковое размещение данных в памяти позволяет в срезе 4
(`edsac-1949-deep`) показать обе программы в два столбца.

## 1. Что в машине

| Часть | Что это | Сколько |
|---|---|---|
| Память | ячейки 0–127; в каждой — одно число | 128 |
| Регистры общего назначения | `A`, `B`, `C` — для вычислений | 3 |
| Индексный регистр | `X` — прибавляется к адресу в команде `STOREX` (и `LOADX`) | 1 |
| Счётчик команд | `PC` — адрес следующей команды | 1 |
| Регистр команды | `IR` — команда, которая выполняется сейчас | 1 |
| Признак «меньше» | `LT` — результат последнего сравнения `CMP` | 1 бит |

Число в ячейке и в регистре — целое со знаком до ±999 999 (шесть десятичных цифр). Это условность
показа, как и у первой машины: диапазон задан, чтобы были видны границы (кубы до 99³ = 970 299
помещаются; EDSAC с его 17 битами на 100 кубов не хватило бы — об этом в срезе 4).

Команда и данные лежат в одной памяти и выглядят одинаково: число. Как и в первой машине, слово
команды — десятичное число, в котором видны поля:

```
слово = КОП × 10000 + РЕГ × 1000 + АДРЕС
        КОП — код операции (0–9), РЕГ — номер регистра (A 0, B 1, C 2, X 3), АДРЕС — 0–999
```

Пример: `ADD A, B` = 5·10000 + 0·1000 + 1 = **50001**; `STOREX A, 28` = 40028; `HALT` = 0.
Программа не меняет собственные команды, но факт «команда — тоже число» остаётся виден:
обучаемый может прочитать слово 50001 в таблице памяти рядом с мнемоникой.

## 2. Система команд

Десять команд. Второй операнд — регистр (`s`), число в самой команде (`n`) или адрес ячейки (`a`).

| Мнемоника | КОП | Действие | Смысл |
|---|---|---|---|
| `HALT` | 0 | остановить машину | стоп |
| `LOAD r, a` | 1 | r := [a] | взять число из ячейки |
| `LOADI r, n` | 2 | r := n | **константа прямо в команде** (immediate) |
| `STORE r, a` | 3 | [a] := r | записать в ячейку |
| `STOREX r, a` | 4 | [a + X] := r | записать **по индексу**: адрес = a плюс регистр X |
| `ADD r, s` | 5 | r := r + s | сложить два регистра |
| `ADDI r, n` | 6 | r := r + n | прибавить константу |
| `SUB r, s` | 7 | r := r − s | вычесть регистр |
| `CMP r, a` | 8 | LT := (r < [a]) | сравнить регистр с ячейкой; результат — в признак |
| `BLT a` | 9 | если LT, то PC := a | перейти, если «меньше» |

Что сознательно **не** включено на 0→1: `LOADX` (чтение по индексу), `JMP` (безусловный переход),
`BEQ`, умножение. Для задачи они не нужны; `LOADX` появится, когда пример потребует читать массив
(первый кандидат — поиск в таблице). Умножения нет намеренно: таблица строится сложением разностей,
как на EDSAC, и программы двух машин сопоставимы строка в строку.

Цикл команды — тот же, что у первой машины, и показывается так же: **выборка** (IR := [PC], PC += 1)
→ **расшифровка** (КОП, РЕГ, АДРЕС) → **исполнение**. Счётчик тактов — один на команду.

## 3. Размещение в памяти

Совпадает с первой машиной, чтобы столбцы в срезе 4 совпадали по адресам.

| Адреса | Что |
|---|---|
| 0–19 | программа |
| 20 | N — число строк таблицы: 10 или 100 (переключатель «10 / 100» меняет только эту ячейку) |
| 21–27 | свободны (у первой машины здесь константы и рабочая ячейка — у этой они не нужны) |
| 28–127 | таблица: [28 + i] = i² (или i³), i = 0…N−1; в начале пуста |

## 4. Программы

### Квадраты: (i + 1)² = i² + (2i + 1)

```
Адрес  Команда         Слово  Смысл
    0  LOADI  A, 0     20000  A — текущий квадрат, i² = 0
    1  LOADI  B, 1     21001  B — разность 2i + 1
    2  LOADI  X, 0     23000  X — индекс i
    3  STOREX A, 28    40028  [28 + i] := i²            ← начало цикла
    4  ADD    A, B     50001  квадрат += разность
    5  ADDI   B, 2     61002  разность += 2
    6  ADDI   X, 1     63001  i += 1
    7  CMP    X, 20    83020  i < N ?
    8  BLT    3        90003  да — следующая строка
    9  HALT                0  стоп
```

Цикл — шесть команд (3–8). Программа квадратов на первой машине — семнадцать команд, из них цикл —
пятнадцать; разница целиком в трёх вещах: индексный регистр вместо переписывания команды, константа
в команде вместо ячейки, счётчик, который сравнивается, а не вычитается до нуля.

### Кубы: (i + 1)³ = i³ + d₁, d₁ += d₂, d₂ += 6 (d₁ = 3i² + 3i + 1, d₂ = 6i + 6)

```
Адрес  Команда         Слово  Смысл
    0  LOADI  A, 0     20000  A — текущий куб
    1  LOADI  B, 1     21001  B — первая разность d₁
    2  LOADI  C, 6     22006  C — вторая разность d₂
    3  LOADI  X, 0     23000  X — индекс i
    4  STOREX A, 28    40028  [28 + i] := i³            ← начало цикла
    5  ADD    A, B     50001  куб += d₁
    6  ADD    B, C     51002  d₁ += d₂
    7  ADDI   C, 6     62006  d₂ += 6
    8  ADDI   X, 1     63001  i += 1
    9  CMP    X, 20    83020  i < N ?
   10  BLT    4        90004  да — следующая строка
   11  HALT                0  стоп
```

Переключатель «квадраты / кубы» меняет программу целиком (ячейки 0–11); «10 / 100» — только ячейку 20.
Так же устроены переключатели первой машины (решение автора, п. 22).

**Проверено интерпретатором 21.10.2026** (скрипт в scratchpad, в репозиторий войдёт как тест сессии):
обе программы при N = 10 и N = 100 дают верную таблицу, ячейки за таблицей остаются нулями.
Число выполненных команд: квадраты — 64 (N = 10) и 604 (N = 100); кубы — 75 и 705.

## 5. Что видно на экране (реализация `register-machine-1960`, режим `emulated`)

Средство визуализации, не код эпохи; на анахронизмы не проверяется (ADR 0003, п. 10).

- **Панель регистров**: `A`, `B`, `C`, `X`, `PC`, `IR` (число и мнемоника), `LT`. Изменившийся
  на такте регистр подсвечивается.
- **Память**: таблица 128 ячеек, как у первой машины: у ячейки видны число и, если оно читается
  как команда, мнемоника. Ячейка, в которую только что записали, подсвечивается; ячейка, на которую
  указывает `PC`, выделена рамкой.
- **Управление**: «Такт», «Прогон», «Сброс»; скорость; переключатели «10 / 100» и «квадраты / кубы».
- **Строка такта**: «Выборка: IR := [7] = 83020. Расшифровка: CMP X, 20. Исполнение: X = 3 < [20] = 10 →
  LT = да.»
- **Счётчики**: тактов и условного времени. Время — порядка 10 мкс на команду (машины 1959–1960:
  IBM 7090 — цикл 2,18 мкс, PDP-1 — 5 мкс; ПРОВЕРИТЬ ДАТУ) — итог для 100 кубов около 7 мс против
  примерно секунды у первой машины при ~650 командах в секунду.

## 6. Заготовка для среза 4: два столбца

Соответствие «одна команда здесь — цепочка команд на EDSAC-машине». Слева — программа квадратов
из раздела 4, справа — программа из `hw-01_cpu-cycle.md` (адреса первой машины).

| Машина с регистрами | Машина с аккумулятором (EDSAC) | Почему длиннее |
|---|---|---|
| `LOADI A, 0`; `LOADI B, 1` | ячейки 20 = 0, 21 = 1 заданы заранее как данные | константы нельзя записать в команду — только в память |
| `LOADI X, 0` | команда в ячейке 2 изначально `T 28` | индекса нет: адрес хранится прямо в команде |
| `STOREX A, 28` | `T 25` · `A 20` · `T 28` | один аккумулятор: сначала очистить, потом взять квадрат, потом записать |
| (индекс сдвигается в `ADDI X, 1`) | `A 2` · `A 24` · `T 2` | чтобы писать в следующую ячейку, программа прибавляет 1 к собственной команде |
| `ADD A, B` | `A 20` · `A 21` · `T 20` | регистров нет: переменные живут в памяти, каждое сложение — через аккумулятор |
| `ADDI B, 2` | `A 21` · `A 23` · `T 21` | константа 2 — в ячейке 23 |
| `ADDI X, 1`; `CMP X, 20`; `BLT 3` | `A 22` · `S 24` · `U 22` · `E 0` | сравнения нет: счётчик уменьшают до нуля и смотрят знак аккумулятора |
| `HALT` | `Z` | — |

Итог столбцов: 10 команд против 17; цикл 6 против 15. Это содержание стоп-кадров среза 4.
