# Формат описания среза (редакция 18.10.2026)

Описание среза — документ для автора, из которого затем получаются файлы содержания.
Лежит в `docs/slices/<трек>-<NN>_<slice-id>.md`; редакции различаются историей git
(в файлах .docx вне репозитория — суффиксом `_r<N>`).

- `<трек>` — код трека: `net` компьютерные сети, `fe` front-end, `hw` аппаратная основа,
  `data` данные, `proc` процесс разработки, `test` тестирование, `arch` архитектура, `lang` языки.
- `<NN>` — порядковый номер в треке; условен (граф частичный), служит для сортировки.
- `<slice-id>` — тот же id, что в `slice.json` и в имени папки `Content/slices/<slice-id>/`.

| Раздел | Что содержит | Куда попадает |
|---|---|---|
| 0. Паспорт | id, название, годы, треки, актуальность, статус, редакция | `slice.json`: id, title, yearFrom/yearTo, tracks, relevance, status |
| 1. Место в графе | непосредственные предшественники (срез, трек, зачем) и последователи | `prerequisites[]`; последователи вычисляются оболочкой |
| 2. Вводимое решение | одна фраза | `introduces` |
| 3. Исторический контекст | даты и события; для автора и era-reviewer | не попадает |
| 4. Тексты для обучаемого | связь назад, ссылка вперёд, пояснение актуальности, «зачем для проверки кода модели» | `linkBack`, `linkForward`, `whyNeededToReviewModelCode` |
| 5. Примеры и реализации | задача; для реализации — стек, режим кода, что в iframe, код для показа | `manifest.json`, папка реализации |
| 6. Процессы и кадры | тип, старт, таблица кадров со стоп-кадрами | `process/<id>.json` |
| 7. Вопросы | ≥ 5; эталонное обоснование; вопрос-продолжение | `questions.json` |
| 8. Остаётся человеку | ПРОВЕРИТЬ ДАТУ; решения автора; проверено автором | не попадает; закрывается до `approved` |
| 9. Расширения | варианты среза; альтернативные процессы; эмуляция | по расширению |

**Срез с незакрытым выбором** описывается с разделом 9 «Варианты» перед паспортом; разделы
0–8 содержат только различающееся. После выбора описание переписывается в полный формат,
а выбор с обоснованием уходит в раздел 8 и в ADR.
