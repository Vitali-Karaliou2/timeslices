# 0008. Проигрывание процесса: расписание считает сервер, сжатие промежутков логарифмическое
Дата: 2026-10-18. Статус: accepted (автор, 18.10.2026; вступает в силу при слиянии PR).

## Контекст
Brief 7.3 требует, чтобы процесс проигрывался по кадрам во времени, многочасовое ожидание проходило
за секунды, а стоп-кадр останавливал воспроизведение и показывал фрагмент кода. В файлах процессов
есть только `at` кадров; правило, как реальный промежуток превращается в экранную задержку, нужно было
выбрать и закрепить. План сессии 05 задал границы: шаг от 0,6 до 3 с при скорости ×1, подпись
«прошло …» у промежутков больше минуты, стоп-кадр всегда останавливает.

## Решение
1. Расписание строит сервер (`Collection/ProcessSchedule`) и отдаёт в странице примера как
   `<script type="application/json">`; JS (`wwwroot/js/process-player.js`) только идёт по шагам
   и делит задержку на скорость ×1/×2/×4. Правила проверяются xUnit-тестами, а не в браузере.
2. Экранная задержка = 0,6 с × (1 + log₂(1 + промежуток в секундах)), не больше 3 с: 1 с → 1,2 с,
   7 с → 2,4 с, от 15 с и дольше — 3 с. Порядок коротких промежутков виден, часы и сутки занимают 3 с.
   Кадры без `at` или с тем же `at` — 0,6 с.
3. Подпись «прошло 3 ч 20 мин» — у промежутков длиннее минуты; секунды — только до часа включительно;
   единицы «сут», «ч», «мин», «с». Подпись — интерфейс оболочки, не текст среза, пометки ЧЕРНОВИК не несёт.
4. Фрагмент кода стоп-кадра берётся из кода для показа, уже выведенного на странице
   (`pre[data-code-file]`), с двумя строками контекста и подсветкой строк `detail.lines`.
5. Без JS проигрыватель скрыт, список кадров со ссылками на строки кода виден целиком.

## Последствия (включая то, что стало труднее)
- Схема процесса не меняется.
- Промежутки от 15 с до суток на экране неотличимы по длительности; различие несёт только подпись
  (а она появляется лишь после минуты). Для прогона 1972 года (часы ожидания) этого достаточно;
  если понадобится «ощущение» длины ожидания между 15 с и минутой — менять формулу здесь.
- Стоп-кадр, чей `codeFile` не входит в `codeFiles` реализации, покажет только пояснение
  (на настоящем содержании это исключено тестом `Directory_StopFrames_PointAtExistingLinesOfCodeFiles`).
- Процессы создания с вариантами (сессия 09) проигрываются тем же механизмом; переключение вариантов — отдельная задача.

## Альтернативы, которые отвергнуты, и почему
- Линейное сжатие с отсечкой (задержка = промежуток, но 0,6…3 с) — все промежутки от 3 с до часов
  неотличимы, а большинство кадров первого набора разделены 1–10 с.
- Расписание в JS — правила пришлось бы тестировать в браузере; план требует, чтобы считал сервер.
- Фрагмент кода в JSON расписания — дублирует уже загруженный код для показа.
