# 0002. Скелет оболочки: вычисляемые состояния, повтор по явному действию, доступ к сборкам по токену
Дата: 2026-10-17. Статус: proposed.

## Контекст
Сессия 01 (docs/plans/session-01-skeleton.md) собрала оболочку по docs/spec/shell-spec.md.
Спецификация не определяла несколько вещей, без которых код не написать: что и когда
сохраняется в `UserSliceState`, что значит «повторное открытие» пройденного среза, как
iframe получает статическую сборку и кто ещё может её получить, где лежит код оболочки,
работающий с содержанием, и на какой версии .NET всё это собирается.

## Решение
1. **Состояния.** В БД хранятся только `InProgress` и `Done` (+ `IsRepeat`). `Unavailable`
   и `Available` вычисляются по графу при каждом запросе, в топологическом порядке. Граф главнее
   записей: если предшественник не пройден, срез недоступен, что бы ни лежало в БД.
   `InProgress` с `IsRepeat = true` считается пройденным для последующих.
2. **Открытие.** GET страницы доступного среза переводит его в `InProgress`. Это единственное
   изменение состояния по GET. «Готово», повтор и сброс — POST с antiforgery-токеном.
3. **Повторное прохождение.** Открытие пройденного среза ничего не меняет. На странице есть
   блок «Повторное прохождение»:
   - если пользователь не продвинулся дальше (нет начатых или пройденных непосредственных
     последующих) — одна кнопка, срез становится просто `InProgress`;
   - иначе выбор: «сбросить последующие» удаляет записи всех транзитивно последующих
     тематических срезов, во всех треках; «не менять» — `InProgress` + `IsRepeat`.
   Так «Готово» с редиректом на ту же страницу не откатывает срез сразу обратно.
4. **«Далее»** — непосредственные последующие тематические срезы (в том числе через межтрековые
   рёбра), которые сейчас не `Unavailable`. Ровно один — переход, несколько — выбор, ни одного —
   сообщение.
5. **Доступ к сборкам.** Сборки отдаются по `/content/{token}/<путь от Content/>`, только файлы
   внутри `implementations/<impl-id>/`. Токен — Data Protection (входит в ASP.NET Core) на пару
   «пример/реализация», живёт 8 часов. Выдаёт его страница примера после проверки, что открыт и срез
   страницы, и срез самой реализации. Реализации, «отыгранные вперёд» на ещё недоступный срез
   (brief 7.2), в выпадающем списке не показываются, и токен на них не выдаётся.
   Почему не cookie: iframe с `sandbox="allow-scripts allow-forms"` без `allow-same-origin`
   работает в непрозрачном источнике, и браузер не шлёт cookie входа на запросы его ресурсов
   (проверено: CSS внутри сборки получал 302 на вход). Токен — сегмент пути, поэтому относительные
   ссылки внутри сборки работают без изменений.
6. **Загрузчик проверяет пути манифеста.** `id` реализации — kebab-case; `entry`, файлы процессов
   и кода не выходят за папку реализации. Иначе приложение не стартует.
7. **Код, работающий с содержанием**, лежит в `src/TimeSlices.Web/Collection/`, состояния — в
   `Progress/`. `Content/` остаётся только содержанием, как требует CLAUDE.md.
8. **Платформа.** .NET 10 (LTS), решение — `TimeSlices.sln` в классическом формате
   (`--format sln`, по умолчанию .NET 10 создаёт `.slnx`). Bootstrap и jQuery из шаблона убраны.

## Последствия
- Добавление среза по-прежнему не требует кода; ошибка в графе или манифесте видна при старте.
- Переход по GET меняет состояние: ссылка, предзагрузка браузера или краулер «откроют» срез.
  Для одного пользователя на 0→1 это приемлемо; для 1→n стоит перевести в явное действие.
- Ссылку на сборку с токеном можно переслать: 8 часов она открывает этот пример без входа.
  Токен не привязан к пользователю. Содержание сборок не секретно; секретны `questions.json`
  и эталонные обоснования, а они наружу не отдаются никогда.
- Ключи Data Protection в Development лежат в профиле пользователя. После их потери старые
  токены не действуют, страница примера выдаёт новые.
- HTTP-уровень (маршрут `/content`, авторизация страниц) проверен вручную и браузером, но не
  автотестами. Для этого нужен `Microsoft.AspNetCore.Mvc.Testing` — новая зависимость, нужно согласие.
- `RequireConfirmedAccount = true` без отправителя писем: самостоятельная регистрация не даёт
  войти, а в Production нет способа создать первого Admin. Пока работаем только в Development.

## Альтернативы, которые отвергнуты, и почему
- **`allow-same-origin` в sandbox.** Cookie начали бы уходить, но скрипт примера получил бы доступ
  к DOM оболочки и к сессии пользователя. Это противоречит духу ADR 0001.
- **Отдавать сборки анонимно.** Нарушает приёмочный критерий 3: содержание недоступного среза
  открывалось бы по прямой ссылке.
- **Хранить `Available` и пересчитывать при изменениях.** Состояние дублировалось бы, а граф
  меняется при каждом добавлении среза.
- **Переводить пройденный срез в `InProgress` при простом открытии**, как буквально написано
  в brief 5.3. Ломает сценарий «Готово → та же страница» и делает просмотр пройденного среза
  разрушительным.
