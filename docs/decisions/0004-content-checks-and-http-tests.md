# 0004. Проверка настоящего содержания и HTTP-тесты оболочки
Дата: 2026-10-18. Статус: proposed.

## Контекст
В сессии 02 в `Content/` появилось настоящее содержание: четыре трека и семь срезов (ADR 0003).
Тесты сессии 01 работали на синтетическом содержании во временной папке. Хук PostToolUse
не проверяет файлы, записанные через Bash. Приёмочные критерии 2 и 3 проверялись только руками.

## Решение
1. **Тест на настоящий `Content/`** (`RealContentTests`). Он фиксирует состав первого набора:
   треки, id срезов, `draft`, отсутствие циклов, межтрековое ребро `net-before-web-1992 → static-page-1995`
   и его действие («Готово» открывает срез). Любое изменение состава набора требует правки этого теста.
2. **`scripts/validate_all.py`** проверяет всё содержание. Ошибкой считаются:
   - json с неизвестным именем вне `implementations/<impl-id>/`;
   - файл процесса, не указанный ни в одном манифесте.
   Прочие json внутри статической сборки пропускаются.
3. **HTTP-тесты** работают через `WebApplicationFactory<Program>` в среде `Testing`:
   - БД — временный файл SQLite;
   - dev-пользователи не сидируются;
   - тестовый обучаемый создаётся со случайным паролем и входит через настоящую форму Identity.
   Для этого в `Program.cs` добавлено `public partial class Program;`.
4. **Эталонные фрагменты текстов в тестах берутся из каталога**, а не литералами: тексты срезов —
   черновики и меняются.

## Последствия (включая то, что стало труднее)
- Изменить состав набора без правки теста нельзя. Это сознательно, но при добавлении восьмого
  среза тест придётся обновлять.
- HTTP-тесты зависят от разметки формы входа Identity UI (имена полей `Input.Email`,
  `Input.Password`, токен antiforgery). Если страницу входа переопределят, тесты нужно будет
  обновить.
- Каждый HTTP-тест логинится заново. Сейчас это незаметно по времени, но растёт с числом тестов.

## Альтернативы, которые отвергнуты, и почему
- **Тестовая схема аутентификации** (подмена входа): быстрее, но не проверяет, что настоящий
  вход работает в связке с политиками доступа.
- **`InternalsVisibleTo` вместо `public partial class Program`**: тоже работает, но
  `WebApplicationFactory` для top-level Program обычно используется с публичным partial-классом.
- **SQLite в памяти для HTTP-тестов**: разделяемое соединение в памяти сложнее согласовать
  с `MigrateAsync` при старте приложения. Временный файл проще.
