# 0006. Кодировка файлов содержания; код для показа и исполняемый код — один файл
Дата: 2026-10-18. Статус: proposed.

## Контекст
Пример «Справочник» (сессия 03) — первое настоящее содержание с кириллицей в статических сборках.
Оболочка отдавала `/content/**` с типом без `charset`, и браузер читал UTF-8 в однобайтовой кодировке.
Код эпохи не может объявить UTF-8 сам (`<META charset>` и UTF-8 в браузерах 1995 года — анахронизм).
Кроме того, правило «код для показа — тот же код, что исполняется» (скилл new-example) нужно было
выполнить и для исполняемой реализации, и для имитаций, которые из iframe без `allow-same-origin`
не могут прочесть `code/*.txt`.

## Решение
1. Все текстовые файлы содержания — в UTF-8; оболочка отдаёт `text/*` из `/content` с `charset=utf-8`.
   Кодировка — условность показа: исторический файл был бы в KOI8-R или CP866, это отмечается
   в `anachronismCheck.notes`, а не в коде.
2. У исполняемой реализации `entry` может лежать в `code/` (`web-1995`: `entry` = `code/index.html`),
   чтобы показывался ровно исполняемый файл, а не копия.
3. Имитация (`emulated`) держит дословную копию кода для показа в
   `<script type="text/plain" data-code="code/…">`; совпадение проверяет тест на настоящее содержание.

## Последствия
- Пример, которому нужна другая кодировка, получит неверный заголовок; до 1→n таких нет.
- Копия кода в имитации — дублирование; при росте числа примеров стоит генерировать её скриптом.
- Схема манифеста не меняется.

## Альтернативы, которые отвергнуты, и почему
- `<META charset="utf-8">` в коде эпохи — анахронизм в показываемом коде.
- Хранить файлы в KOI8-R — оболочка показывает код как UTF-8, и показ сломался бы.
- Две копии `index.html` (корень и `code/`) — нарушает «не два разных кода».
