# 0015. Навигация при учёте по срезу; детали машины с регистрами и «Своей программы»
Дата: 2026-10-21. Статус: proposed.

## Контекст
ADR 0014, п. В перевёл учёт прохождения на пару «пользователь × срез», а тематический срез оставил
единицей навигации. Сессия 08 реализовала это и машину с регистрами (docs/spec/register-machine.md);
по ходу пришлось решить несколько вопросов, которых нет ни в ADR 0014, ни в спецификации.

## Решение
1. **Навигация.** «Что будет после» на странице среза — по одному пункту на каждый последующий срез;
   трек пункта — текущий (`?track=`), если срез в нём есть, иначе трек подписи ребра, иначе первый трек
   среза. «Далее» предлагает только открытые последующие срезы текущего трека; если их нет — переход
   в другие треки. «Что было до» показывает предшественника в текущем треке, если он в нём есть.
   Одно ребро на пару срезов (подпись — один трек), а не по ребру на каждый общий трек.
2. **Миграция незавершённых попыток.** Если у пользователя по одному срезу было несколько незавершённых
   попыток (из разных треков), открытой остаётся последняя; остальные получают статус `Returned`
   с комментарием-пояснением без экзаменатора — иначе не создать уникальный индекс «одна открытая
   попытка на срез». Попытки не удаляются.
3. **Время кадров с долями миллисекунды** показывается в микросекундах («10:00:00,000040»); поле `at`
   и схема не меняются.
4. **Переполнение машины с регистрами не проверяется.** ±999 999 — условность показа; у кубов при
   N = 100 последний проход оставляет в A число 1 000 000, которое в таблицу не пишется.
5. **Слово 0 читается как HALT**, любое другое число — как команда, только если его поля допустимы
   (ADD/SUB — регистр во втором операнде, BLT — без регистра); иначе у ячейки нет мнемоники, а её
   исполнение — останов с объяснением.
6. **Ассемблер «Своей программы»** — `assembler.js` без DOM. Проверка из C# без новых зависимостей:
   дубликат на C# и одна таблица фикстур (`tests/TimeSlices.Tests/Fixtures/register-assembler.json`);
   JS сверяет `scripts/check_assembler.js`, а тест на C# вызывает его, если в системе есть `node`.
   Строка без адреса занимает ячейку после предыдущей; запись в ячейку 20 и в 28–127 — ошибка;
   при любой ошибке в память ничего не пишется.

## Последствия (включая то, что стало труднее)
- Тексты ошибок ассемблера живут в двух местах (JS и C#); расхождение ловит таблица фикстур,
  но только там, где есть `node`, — иначе сверку JS запускают вручную.
- Без `node` тест `AssemblerJs_MatchesFixtureTable_WhenNodeIsAvailable` проходит, ничего не сверив
  (пишет об этом в вывод).
- HTTP-тесты, написанные до сессии 08, получают обучаемого с пройденными eniac → edsac → машина
  с регистрами (`ShellFactory.HardwareStart`): точка входа коллекции сменилась.

## Альтернативы, которые отвергнуты, и почему
- Рёбра по каждому общему треку (eniac → edsac в `foundations` и в `hardware`): на странице среза
  предшественник показывался бы дважды, а «Далее» предлагал бы один и тот же срез в двух треках.
- Запуск JS из C# через движок (Jint и т. п.) — новая зависимость.
- Проверка переполнения с остановом — ломает утверждённую программу кубов при N = 100.
