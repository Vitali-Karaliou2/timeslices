## Часть А. Прохождение по срезу (изменение схемы данных, ADR 0014, п. В)
1. Убрать `TrackId` из `UserSliceState` и `Attempt`. Уникальность — (UserId, SliceId) для состояния.
2. Миграция `ProgressBySlice`. Строки состояния слить по (пользователь, срез), взяв старшее состояние; признак `IsRepeat` — логическое ИЛИ. Попытки не удалять. Миграцию проверить на базе с тестовыми строками: два трека одного среза → одна строка.
3. `SliceProgressService`, `SelfCheckService`, страницы `Slice`, `Example`, `Check` и главная. Состояние тематического среза в каждом треке = состояние среза. Доступность по-прежнему вычисляется по графу. Параметр `?track=` в адресах остаётся для навигации: из какого трека пришли и что показывать в «Что было до / после».
4. `prerequisites[].track` — только подпись ребра. На подсчёт не влияет.
5. Тесты:
   - срез, пройденный в одном треке, пройден и в другом;
   - попытка сдачи одна на срез;
   - миграция слияния (если есть тестовая инфраструктура для миграций — иначе юнит-тест функции слияния).

### 4. Допущения, принятые за автора; ПРОВЕРИТЬ ДАТУ
