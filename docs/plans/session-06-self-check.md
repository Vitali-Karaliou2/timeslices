# Сессия 06. Контроль знаний: самопроверка, демо-экзаменатор, регистрация

Ветка: та, что назначит облачная среда (имя — в отчёте). Ожидаемый результат — PR в `main`: автор
может зарегистрироваться, пройти срез, ответить на вопросы, отправить сдачу и под ролью экзаменатора
подтвердить или вернуть её. `dotnet test` и `validate_all.py` зелёные.

Прочитай: CLAUDE.md; **ADR 0011** (решения и схема данных — источник этого плана); ADR 0002, 0009;
brief 5.3, 8.2, 8.3; `docs/spec/manifest-schema.md` (формат `questions.json`); `docs/acceptance.md`.

## Шаги
1. **Модель данных и миграция** — ровно по разделу «Схема данных» ADR 0011. Миграция
   `dotnet ef migrations add SelfCheck`.
2. **Регистрация (Development).** `RequireConfirmedAccount = false` только в Development; новый
   пользователь получает роль Learner. На `/admin` — выбор роли у каждого пользователя (только Admin).
   В Production поведение прежнее.
3. **Страница контроля знаний** `/slices/{id}/check` — доступна, когда срез «в процессе» или «пройден».
   - Вопросы по одному, в порядке `questions.json`; поле для свободного ответа; «Ответить».
   - После сохранения ответа — эталонное обоснование и вопрос-продолжение (`followUpTemplate`,
     `{answer}` — первые 300 символов ответа, HTML-экранирование), поле для ответа на продолжение.
   - Затем самооценка: «совпал», «частично», «не совпал» — и следующий вопрос.
   - В конце — «Отправить на подтверждение»; до этого можно вернуться к любому вопросу и посмотреть,
     но не изменить уже сохранённый ответ.
   - Значок «черновик» у вопросов и эталонов — по ADR 0009.
4. **Признаки (скрытые от обучаемого).** Небольшой JS на странице вопроса считает активное время ввода
   и число событий `paste` и отправляет их вместе с ответом скрытыми полями; сервер ставит `ShownAt`
   при выдаче вопроса и `AnsweredAt` при сохранении. Обучаемому эти значения нигде не показываются
   (тест: в HTML страниц обучаемого их нет). JS — без библиотек.
5. **Эталон не уходит раньше времени.** Сервер отдаёт `referenceReasoning` только для вопросов, на
   которые в этой попытке уже сохранён ответ. Тест: запрос страницы вопроса до ответа не содержит
   текста эталона.
6. **Состояния сдачи** — выводятся из `Attempt` (ADR 0011, п. 4): на главной и на странице среза рядом
   с «пройден» — «в процессе сдачи», «ожидает подтверждения», «подтверждён экзаменатором»,
   «возвращён» (с комментарием экзаменатора). Повторная сдача после возврата — новая попытка.
7. **Демо-экзаменатор** `/examiner` (роли Examiner и Admin): список отправленных попыток
   (обучаемый, срез, дата отправки, статус); страница попытки — по каждому вопросу: вопрос, ответ,
   продолжение, ответ на него, самооценка, время, активное время, вставки, эталон. Кнопки
   «Подтвердить» и «Вернуть» (комментарий обязателен), POST с antiforgery. Обучаемый к `/examiner`
   доступа не имеет (тест: 403).
8. **Тесты** (xUnit + HTTP): переходы статусов попытки; эталон скрыт до ответа; признаки не видны
   обучаемому и видны экзаменатору; `/examiner` — 403 для Learner; подтверждение и возврат;
   регистрация в Development даёт роль Learner.

## Проверка и PR
1. `dotnet build`, `dotnet test`, `python3 scripts/validate_all.py` — зелёные.
2. Сквозной сценарий вручную (Playwright, скриншоты в `docs/plans/session-06/`): регистрация нового

   попытка → подтверждение.
3. `code-reviewer` на ветке (особое внимание: авторизация, утечка эталона, XSS в `{answer}`).
   `era-reviewer` не нужен — содержания эпохи в сессии нет.
4. Отчёт по скиллу `session-report` в `## Итог` этого файла; PR в `main`.

## Не делать в этой сессии
Оценку ответов моделью и любые вызовы внешних API; закреплённого экзаменатора и рекомендации пяти

## Итог
Ветка: `claude/gracious-einstein-vqqucg`.

### 1. Сделано
- **Модель данных** строго по ADR 0011: `Attempt`, `Answer` и миграция `SelfCheck`. Дополнительно — индексы: одна незавершённая попытка (`InProgress`/`Submitted`) на тематический срез (`IX_Attempts_Open`, фильтрованный уникальный) и один ответ на вопрос в попытке. Каталог читает `questions.json` (`ContentCatalog.QuestionsOf`); вопросы в БД не копируются.
- **Контроль знаний** `/slices/{id}/check`. Порядок: «Начать», затем вопросы по одному. По каждому вопросу: ответ → эталон и продолжение (`{answer}` — первые 300 символов ответа, экранирование делает Razor) → ответ на продолжение → «совпал / частично / не совпал». В конце — «Отправить на подтверждение». Можно открыть любой уже начатый вопрос и посмотреть его, но не изменить. У вопросов, эталонов и продолжений стоит значок «черновик» (ADR 0009). Эталон берётся только из сохранённого ответа этой попытки.
- **Признаки.** `wwwroot/js/self-check.js` без библиотек считает активное время ввода и число вставок. Сервер ставит `ShownAt` из зашифрованной отметки в форме и `AnsweredAt` по своим часам. Признаки видны только на `/examiner/attempt/{id}`.
- **Состояния сдачи** выводятся из последней попытки: «в процессе сдачи», «ожидает подтверждения», «подтверждён экзаменатором», «возвращён». Они показаны на главной, на странице среза и на странице сдачи. На странице среза у возврата виден комментарий экзаменатора и ссылка «Сдать заново», которая начинает новую попытку.
- **Демо-экзаменатор** `/examiner` (Examiner и Admin): список попыток, страница попытки, «Подтвердить» и «Вернуть» (комментарий обязателен), POST с antiforgery. Обучаемый получает 403: вошедший пользователь без роли теперь получает 403, а не перенаправление. Для ответов с ошибкой без тела добавлена страница `Pages/Status`.
- **Регистрация.** Своя страница `Areas/Identity/Pages/Account/Register` выдаёт роль Learner. В Development пользователь входит сразу; в остальных средах, как раньше, нужно подтверждение почты. На `/admin` есть выбор роли у каждого пользователя, кроме себя.
- **Тесты.** Добавлено 20, всего 138: `SelfCheckTests` (сервис) и `SelfCheckHttpTests`, `StatusCodeTests`, `RegistrationTests` (HTTP). Черновик `docs/decisions/0012-self-check-implementation.md` (proposed).

### 2. Сознательно не сделано и почему
- **Время ответа на продолжение.** ADR 0011, п. 2 требует время «от показа до отправки» и для продолжения, но в схеме нет `FollowUpShownAt`/`FollowUpAnsweredAt`. Схему не менял: нужно ваше согласие. Для продолжения сохраняются только активное время и число вставок.
- **`ShownAt` — последний показ, а не первый.** Перезагрузка страницы вопроса сбрасывает время. Чтобы сохранять первый показ, нужно хранилище вне формы, то есть схема или ADR.
- **Подписи интерфейса без значка «черновик»**: «Начать», «Ответить», «Насколько ваш ответ совпал с эталоном?», «Отправить на подтверждение», «Сдать заново», названия состояний сдачи, сообщения об ошибках. Это интерфейс оболочки, а не текст среза, как в сессии 05. Прошу утвердить формулировки.
- Оценка моделью, закреплённый экзаменатор, рекомендации, почта, правка содержания — по плану не делались.
- `era-reviewer` не вызывался: содержания эпохи в сессии нет.

### 4. Допущения, принятые за автора
- Сдача открыта, когда срез «в процессе» или «пройден» и у него есть вопросы. После подтверждения новую попытку начать нельзя; после возврата — можно.
- Вперёд текущего вопроса переходить нельзя: вопросы идут по одному.
- Ответ и продолжение обязательны и не длиннее 10 000 символов; комментарий экзаменатора — не длиннее 4 000.
- Активное время — сумма промежутков между событиями ввода, если промежуток не длиннее 5 с. Сервер обрезает его до прошедшего времени. Без JS признаки равны 0.
- У пользователя одна роль. Свою роль администратор не меняет.
- Экзаменатор может решить и собственную сдачу (ADR 0011: «один человек в двух ролях»).
- ПРОВЕРИТЬ ДАТУ: нет, содержания эпохи в сессии нет.

### 5. Черновик ADR
`docs/decisions/0012-self-check-implementation.md` (proposed):
- `ShownAt` передаётся через форму, зашифрованный Data Protection.
- Признаки ограничивает сервер.
- Шаги сдачи и решения экзаменатора пишутся условными UPDATE, плюс фильтрованный уникальный индекс.
- Без нужной роли — 403 вместо перенаправления, страница `Status` для ответов без тела.
- Своя страница регистрации с ролью Learner, одна роль на пользователя.
- Последствие: время ответа на продолжение не хранится, пока не изменена схема.
