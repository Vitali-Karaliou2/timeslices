## Часть 2. Проигрыватель процессов
**Цель (brief 7.3):** процесс проигрывается по кадрам во времени; многочасовое ожидание проигрывается
за секунды; на стоп-кадре воспроизведение останавливается и показывает фрагмент кода с пояснением.

1. **Расписание считает сервер, не JS.** Класс в `Collection/` (например, `ProcessSchedule`), который
   по `Process` строит шаги: кадр в порядке `order`; реальный промежуток до следующего кадра по `at`;
   экранная задержка; подпись промежутка. Правила:
   - экранная задержка = реальный промежуток, сжатый так, чтобы шаг длился от 0,6 до 3 с
     (при скорости ×1); переключатель скорости ×1 / ×2 / ×4 делит задержку;
   - промежуток больше 1 минуты показывается подписью «прошло 3 ч 20 мин» (по-русски, без секунд
     для промежутков больше часа), а длится на экране не больше 3 с;
   - кадры без `at` или с одинаковым `at` идут с минимальной задержкой;
   - стоп-кадр всегда останавливает воспроизведение.
   xUnit-тесты на эти правила (порядок, сжатие, подпись, кадры без времени, остановка).
2. **Страница примера.** Под каждым процессом — проигрыватель: «Проиграть», «Пауза», «Назад»,
   «Вперёд», скорость, текущее время сюжета (`at`) крупно. Текущий кадр подсвечен в списке кадров;
   список остаётся видимым и без JS (прогрессивное улучшение). Расписание отдаётся в странице как
   `<script type="application/json">`; логика — один файл `wwwroot/js/process-player.js`, без
   библиотек и сборщиков. Комментарий в начале файла: «средство визуализации, не код эпохи».
3. **Стоп-кадр.** При остановке под кадром показывается `detail.explanation` и фрагмент
   `detail.codeFile`, строки `detail.lines`, с подсветкой этих строк; кнопка «Дальше» продолжает.
   Фрагмент берётся из уже загруженного кода для показа (сервер знает файлы реализации).
4. **Доступность.** Кнопки — настоящие `<button>`, управление с клавиатуры; текущий кадр объявляется
   через `aria-live="polite"`.
5. **Ручная проверка** (Playwright, скриншоты в отчёт): проиграть `ftp-session` и `request-response`
   на скорости ×4 — остановки на стоп-кадрах, фрагмент кода с подсвеченными строками, подпись
   промежутка там, где она есть.

## Часть 3. Ошибка оболочки со страницы входа
Сессия 03 нашла: на странице входа `site.js` и скрипты проверки форм перенаправляются на вход
(три `SyntaxError` в консоли). Статические файлы оболочки (`wwwroot`) должны отдаваться без входа;
`/content/**` — по-прежнему только по токену. HTTP-тест: анонимный `GET` файла из `wwwroot/js` → 200.
