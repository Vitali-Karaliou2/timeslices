# Приёмочные критерии оболочки, стадия 0→1

Каждое утверждение должен уметь проверить посторонний человек без помощи автора,
за 15 минут, на свежем клоне репозитория. Утверждение, которое нельзя так проверить,
в этот список не попадает.

1. `dotnet build` и `dotnet test` проходят на свежем клоне в облачной сессии и на локальной
   машине с .NET LTS; тестов не меньше пяти, и они покрывают пункты 3–6.
2. После `dotnet run` по адресу `/` открывается страница входа; три dev-пользователя
   (обучаемый, экзаменатор, администратор) входят и видят главную страницу с треками и срезами.
3. Срез, у которого не пройден хотя бы один предшественник, показан на главной как
   «недоступен», и прямой переход по его URL не открывает содержание.
4. Нажатие «Готово» на доступном срезе переводит его в «пройден» и делает доступными
   те срезы, у которых все предшественники теперь пройдены; «Далее» переводит на следующий
   (при нескольких — предлагает выбор).
5. Повторное открытие пройденного среза даёт выбор «сбросить последующие / не менять»;
   при «не менять» последующие срезы остаются пройденными, а сам срез помечен «повторно».
6. Страница примера показывает работающую реализацию в iframe из статической папки
   реализации; при наличии нескольких реализаций их можно переключать выпадающим списком;
   рядом виден код для показа.
7. Добавление нового среза — это добавление папки с `slice.json` (и примеров) без изменения
   кода оболочки; `validate_manifest.py` проходит; срез появляется на главной после перезапуска.
