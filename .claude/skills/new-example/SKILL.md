# Создание примера и реализации

## Правила (из CLAUDE.md, повторены, потому что здесь они критичны)
- Реализация — самостоятельная папка; оболочка её не компилирует, а показывает `entry` в iframe.
- Историческая достоверность важнее красоты: только то, что существовало в год среза.
  Любое сомнение — `ПРОВЕРИТЬ ДАТУ:` в коде (комментарием) и в `anachronismCheck.notes`.
- `codeMode`: `executable` для HTML/CSS/JS/Python/C#; `emulated` для машинного кода, ассемблера,
  FORTRAN/COBOL/LISP — тогда вместо исполнения показываются готовые результаты прогонов.
- Один пример может иметь несколько реализаций на разных срезах; функциональность одна,
  меняется только решение. Не меняй задачу, чтобы она «лучше легла» на срез.

## Шаги
1. Прочитай `docs/spec/manifest-schema.md`.
2. Папка `…/examples/<example-id>/`: `manifest.json`; `implementations/<impl-id>/` с `entry`,
   `code/`, `process/`.
3. Код для показа (`code/`) — это тот же код, что исполняется, но с пометками ключевых строк
   в `codeFiles[].note`. Не два разных кода.
4. Процесс: `type: execution` обязателен хотя бы один; `creation` — по задаче. Каждый кадр —
   `at` (дата/время в сюжете) и `durationNote` (почему шаг занял столько). Минимум один
   стоп-кадр с `detail` (фрагмент кода + пояснение).
5. Проверка: `python3 scripts/validate_manifest.py manifest.json`; открой `entry` в браузере
   оболочки (dotnet run) и убедись, что iframe загружается без ошибок в консоли.
6. `anachronismCheck.by = "pending"` всегда: на `human` меняет только автор.
7. В отчёте — список всех допущений о датах.
