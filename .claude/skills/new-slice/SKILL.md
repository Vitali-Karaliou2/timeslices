# Создание нового среза

Срез — единица содержания. Его «готовность» определена в brief (раздел 10.3); этот скилл
делает всё, что можно сделать до проверки человеком, и явно оставляет человеку то,
что делегировать нельзя (brief 12.2).

## Входные данные (спроси, если не даны в задаче)
1. `id` среза (kebab-case), название, годы (точность 1–2 года), трек(и).
2. Вводимое решение одной фразой.
3. Предшественники: список `{slice, track, why}`. Межтрековые рёбра — предлагай как предложения,
   не утверждай.
4. Пометка актуальности `a|b|c` — предложи и обоснуй; утверждает автор.

## Шаги
1. Прочитай `docs/spec/manifest-schema.md` и один уже существующий срез как образец
   (если есть), чтобы не выдумывать поля.
2. Создай `src/TimeSlices.Web/Content/slices/<id>/slice.json` со `status: "draft"`.
   Поле `whyNeededToReviewModelCode` — обязательно; если ответ пуст, остановись и спроси:
   по brief (риск 3) такой срез в коллекцию не включается.
3. Для каждого примера — скилл `new-example` (одна реализация минимум, один процесс
   с хотя бы одним стоп-кадром).
4. Создай `questions.json`: не менее пяти вопросов в свободной форме, каждый с эталонным
   обоснованием и шаблоном вопроса-продолжения по ответу пользователя. Без вариантов ответа.
5. Прогони `python3 scripts/validate_manifest.py` для каждого созданного json.
6. Запусти субагента `era-reviewer` на папке среза. Его замечания — в отчёт; не «исправляй
   даты» сам, если не уверен: помечай `ПРОВЕРИТЬ ДАТУ`.
7. Все тексты, которые увидит обучаемый, начинай с пометки `ЧЕРНОВИК:`.
8. Добавь срез в приёмочный тест графа (tests/…/GraphTests) — срез должен быть достижим
   и не создавать цикла.
9. В отчёте перечисли: что осталось человеку — (а) проверка на анахронизмы, (б) утверждение
   текстов, (в) ответ «зачем для проверки кода модели», (г) пометка актуальности.
