# TimeSlices — обучающее приложение «Временны́е срезы»

## Что это
Обучающее приложение: история разработки ПО как частично упорядоченная коллекция
временны́х срезов (DAG) с работающими примерами «до/после». Цель — тренировать
способность судить о чужом (в т. ч. машинном) коде, а не знание истории.
Полное описание замысла: @docs/brief/TimeSlices_Project_Brief_RU.md
Терминология: трек, срез, тематический срез, пример, реализация, процесс, кадр, стоп-кадр
(см. раздел 0 brief). Используй эти слова в коде и комментариях, не придумывай синонимов.

## Стадия
0→1. Один человек плюс модель (к работе могут подключаться ещё два разработчика
со своими аккаунтами — тот же репозиторий, свои ветки). Первый набор — семь срезов
(docs/decisions/0003-first-set-composition.md; он главнее раздела 10.2 brief). Описания срезов —
`docs/slices/`, формат — `docs/spec/slice-description-format.md`. Оболочка тонкая; примеры — изолированные статические сборки.

## Стек и команды
- .NET LTS, ASP.NET Core (Razor Pages), EF Core + SQLite (файл `app.db` в корне, в .gitignore).
- ASP.NET Core Identity, роли: Learner, Examiner, Admin. Dev-пользователи сидируются при старте.
- Сборка: `dotnet build TimeSlices.sln`
- Тесты: `dotnet test TimeSlices.sln`
- Запуск: `dotnet run --project src/TimeSlices.Web` (http://localhost:5000)
- Миграции: `dotnet ef migrations add <Name> --project src/TimeSlices.Web`
- Проверка манифеста примера: `python3 scripts/validate_manifest.py <path/to/manifest.json>` (на Windows — `python`)
- В облачной сессии .NET ставится хуком SessionStart (scripts/install_dotnet.sh); если `dotnet`
  не найден — выполни `bash scripts/install_dotnet.sh` и добавь `$HOME/.dotnet` в PATH.

## Структура репозитория
- `src/TimeSlices.Web/` — оболочка (единственный ASP.NET-проект).
- `src/TimeSlices.Web/Content/` — содержание коллекции (НЕ код оболочки):
  - `tracks.json` — треки; `slices/<slice-id>/slice.json` — срез, его предшественники, тексты;
  - `slices/<slice-id>/examples/<example-id>/manifest.json` — пример и реализации;
  - `.../implementations/<impl-id>/` — статическая сборка (index.html и всё, что ей нужно),
    `code/` — код для показа, `process/<process-id>.json` — кадры и стоп-кадры;
  - `.../questions.json` — вопросы для контроля знаний с эталонными обоснованиями.
- `tests/TimeSlices.Tests/` — xUnit: приёмочные тесты оболочки (docs/acceptance.md).
- `docs/` — brief, спецификация оболочки, приёмочные критерии, записи решений (ADR), планы сессий.
- `.claude/` — skills, agents, settings (хуки). Всё в репозитории: облачные сессии ничего
  не берут с локальной машины.

## Жёсткие правила
- Оболочка и примеры разделены: оболочка не знает стек примера и никогда его не компилирует;
  пример встраивается через iframe из его статической сборки. Оболочка читает только манифесты.
- Каждый пример — папка с манифестом. Схема манифеста: docs/spec/manifest-schema.md.
  Любое изменение схемы манифеста или схемы данных — только после моего согласия.
- Историческая достоверность: не вводить в пример конструкций, языковых средств, библиотек,
  тегов и CSS-свойств, не существовавших в год среза. При любом сомнении — пометить в коде
  и в отчёте `ПРОВЕРИТЬ ДАТУ: <что именно>` и спросить меня. Не угадывать.
  Правило касается кода и разметки, которые показываются как код эпохи. Средство визуализации
  (имитация терминала или меню, скрипт-двойник сервера, проигрыватель кадров) на анахронизмы
  не проверяется, но в коде помечается комментарием «средство визуализации, не код эпохи».
  Расшифровки сеансов (FTP, Gopher, HTTP, распечатки прогонов) — реконструкция, а не стенограмма
  (ADR 0007): человек проверяет команды, коды ответов и порядок шагов — то, на чём строится вывод
  обучаемого; дословные тексты сообщений серверов помечаются как реконструкция в `anachronismCheck.notes`.
- Не эмулировать настоящие машины; использовать учебную машину и готовые результаты прогонов.
- Никаких новых NuGet/npm-зависимостей без моего согласия. Разрешено заранее: EF Core, SQLite,
  Identity, xUnit, Microsoft.AspNetCore.Mvc.Testing (только тестовый проект; `dotnet add package`
  заблокирован хуком — добавляй `PackageReference` правкой .csproj). Фронтенд оболочки — без сборщиков и фреймворков (обычные Razor + немного JS).
- Не делать на 0→1 (раздел 10.4 brief): экзаменатор дальше демо-режима; эмуляция настоящих машин;
  дублирование раннего кода на Python; пользовательские примеры; распределённость и масштаб.
- Тексты, которые видит обучаемый (страницы срезов, вопросы, пояснения), — черновики: помечай
  их как `ЧЕРНОВИК` до моего утверждения; я снимаю пометку сам.
- Авторские права: материалы из загруженных книг — только для точности, не воспроизводить их текст.

## Границы делегирования
Ты решаешь: структуру кода оболочки, реализацию по спецификации, черновики текстов, наборы вопросов,
предложения межтрековых рёбер (как предложения).
Ты спрашиваешь: состав срезов и треков; любое утверждение о дате появления технологии;
любое изменение схемы данных или манифеста; формулировки, которые видит обучаемый; новые зависимости;
всё, что нельзя откатить (удаление, force-push, изменение CI).

## Как работать в сессии
1. Прочитай задачу сессии в `docs/plans/` (если есть файл на эту сессию) и `docs/decisions/`.
2. Explore → Plan → Code → Commit. План — коротко, в начале ответа. Не переписывай то, что не просили.
3. Коммить и пушь часто, небольшими коммитами, в ветку сессии (не в `main`). PR создавай только
   когда задача сессии завершена и `dotnet test` зелёный.
4. Перед PR — вызови субагента `code-reviewer`; для содержания срезов — `era-reviewer`,
   но только на настоящем содержании (примеры, код эпохи, тексты срезов), не на заглушках.
5. Если чего-то не хватает (доступ, секрет, инструмент) — скажи, чего именно, и остановись.
   Не подменяй, не мокай, не угадывай.

## Отчёт после существенной работы (обязательный формат)
1. Сделано.
2. Сознательно не сделано и почему.
3. Проверка: что именно запущено (команды) и с каким результатом (вывод кратко).
4. Допущения, принятые за меня; все даты, в которых не уверен (`ПРОВЕРИТЬ ДАТУ`).
5. Что предлагаю записать в docs/decisions (черновик ADR одним абзацем).
